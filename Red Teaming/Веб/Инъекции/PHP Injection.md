PHP инъекция - уязвимость, которая позволяет атакующему выполнить свой PHP-код на стороне сервера. Это становится возможным, когда в PHP коде неправильным образом используются потенциально опасные функции.
Пример уязвимого кода:
```PHP
<?php
if (isset($_GET["page"])) {
 $page = $_GET["page"];
 include $page . ".php";
}
?>
```
## Потенциально опасные функции
- `include()`
- `require()`
- `require_once()`
- `include_once()`
- `eval()` - выполнение PHP кода, пейлоады: `<?php phpinfo(); ?>`, `phpinfo()`
- `preg_replace()` - функция осуществляет поиск вхождений по регулярному выражению $pattern в строке $string и замену на новые значения, она является опасной, если в регулярном выражении используется модификатор `e` (`PREG_REPLACE_EVAL`), благодаря которому до замещения функция выполнит полученную строку, как PHP код
- `preg_replace_callback()`- функция формирует массив из совпадений по регулярному выражению в строке и передает его на вход лямбда-функции
- `create_function()` - функция создает лямбда-функцию, которая принимает на вход строку с аргументами и выполняет PHP код
## [[File Inclusion]]
PHP инъекция может быть выполнена с помощью Local File Inclusion (LFI) и Remote File Inclusion (RFI) 
PHP-файлы, которые нужно исполнить, подключаются с помощью функций `include` и `require`. Они обе подключают и выполняют файл. Обе функции могут подключать как локальные (LFI), так и удалённые файлы (RFI).
### Загрузка файлов
Если найдена LFI, но возможности вызвать RFI нет, можно попробовать найти функционал загрузки пользовательских файлов. Если функционал загрузки файлов позволяет напрямую загружать и исполнять PHP-файлы, то наличие LFI уже не требуется - достаточно загрузить шелл и обратиться к нему напрямую (например, `/uploads/shell.php`). Это самый простой и быстрый путь к RCE. Однако чаще всего разработчики пытаются ограничить загрузку только изображениями или документами. В таком случае атакующему нужно обойти проверки.
#### Обход проверки расширения
Обычно сервер проверяет только расширение файла (например, разрешает загружать только `.jpg` или `.png`). Часто блокируется только `.php`, но существуют другие расширения, которые обрабатываются интерпретатором PHP. Наиболее распространённые расширения PHP: `.php`, `.php3`, `.php4`, `.php5`, `.php7`, `.pht`, `.phps`, `.phar`, `.phpt`, `.pgif`, `.phtml`, `.phtm`, `.inc`. 
Если такие расширения не попали в список запрещённых, атакующий может загрузить файл с таким расширением, сервер выполнит его как обычный PHP-скрипт.
Также возможно использование двойного расширения: `shell.php.jp`; вставка спецсимволов: `shell.php;.jpg`, `shell.php%00.jpg`.
#### Обход проверки MIME
Разработчики могут использовать заголовок `Content-Type` для проверки типа файла, однако проблема в том, что MIME полностью контролируется пользователем и легко подменяется. Таким образом, можно загрузить PHP-код с поддельным заголовком `Content-Type: image/jpeg`.
#### Обход проверки содержимого (magic bytes)
Иногда сервер проверяет первые байты файла (magic bytes), чтобы убедиться, что это действительно изображение или другой разрешённый формат. Такие проверки можно обойти, создав polyglot-файл, то есть файл, который одновременно является корректным изображением и содержит исполняемый PHP-код. При открытии файл будет выглядеть как картинка, но, если его обработать через LFI или вызвать напрямую, сервер выполнит встроенный код.
### Как искать LFI и RFI
Так как LFI и RFI, по сути, одинаковые уязвимости (RFI - расширенная версия LFI), ищутся они одинаково. Поскольку LFI возникает, когда пути, переданные в `include` или `require`, не фильтруются должным образом, в blackbox методе тестирования необходимо искать скрипты, которые принимают имена файлов в качестве параметров.
